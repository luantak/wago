# Independent reviews

Correctness reviewer: GPT-6 Astra, independent context, read-only. Performance reviewer: GPT-6.1 Sol, independent context, read-only. Both inspected actual production code, the baseline diff, tests, and raw evidence. Neither edited files or ran tests or benchmarks. The performance reviewer read all six final closed-image samples and checked their production hashes. The author independently verified each finding.

The correctness review found no confirmed production defect. It found that state-equivalence tests could pass after early scalar rejection, and that nonzero ascending counters and steps two/four lacked direct coverage. Added tests now assert `region-loop-map32 == 1` and require fast execution. A separate nondivisible case uses valid planned ranges, requires the diagnostic fallback trap, and checks that no store occurred. The final read-only follow-up confirmed that these test-proof gaps are resolved. The pressure test remains a fallback/state-equivalence check. See `results/final-validation.txt`.

The performance review found three costs: higher one-call public cost, large per-function code/frame growth, and narrow real selection. These costs remain in the report. It also found two measurement defects. The existing `benchmarkCompileModule` helper did not close code images. The experiment now uses matched explicit feature masks and closes each image; the six-sample follow-up replaces those compile controls. `run.py` could append measurements into an existing directory while overwriting its manifest. It now refuses a nonempty output directory.

The final performance review checked 18 backend cases and six public cases, each with six samples. It confirmed repeated execution gains, the accepted heap-image allocation increase 30→32, unchanged rejected heap-image allocations, and inconclusive small ordinary compile differences under high variance. It identified code-image underestimation as a source-based explanation. A later author allocation profile confirmed one encoder growth and one final-image growth per accepted compile. That profile is saved, and its profiled times are not used as benchmark results.
